## 〇、工程约束（先钉死，全程不偏离）

| 约束 | 内容 |
|---|---|
| 交付形态 | **单个 HTML 文件**，双击即玩，无外部运行时依赖（无 CDN、无 npm 包在运行期） |
| 开发形态 | 源码拆成模块（便于测试与阅读），用**零依赖的 Node 脚本**内联打包成单文件 |
| 渲染 | **Canvas 2D 代码绘制**，不用任何位图美术资源 |
| 逻辑与渲染解耦 | 逻辑层纯函数、不碰 DOM/Canvas；渲染层只读取逻辑状态。为 M7 的 Three.js 升级预留接口 |
| 无障碍 | 边线点击热区 ≥ 24px；键盘可作为后备输入（可选，非必须） |
| 术语审查 | 产出文案中**不得出现**：边、顶点、回路、格点、算法、Slitherlink、数回 |
| 商标回避 | 源码技术注释可写 slitherlink，**所有用户可见文案与宣传物料不得出现**该词与「数回」 |
| 审美红线 | 水面饱和度 ≤ 30%；灯火仅出现在聚落；缓动统一 ease-out，禁弹跳回弹 |

**目录结构（目标态）**

```
waterweave/
├── index.html                 # 开发期调试壳（ES module 直接加载）
├── src/
│   ├── logic/
│   │   ├── topology.js        # 网格索引、边/水口寻址、邻居表
│   │   ├── model.js           # 关卡数据模型 + 玩家状态模型
│   │   ├── validator.js       # 实时校验器（只提示，不判负）
│   │   └── solver.js          # 求解器（仅开发期使用，不进最终包）
│   ├── render/
│   │   ├── palette.js         # 色板常量（唯一色值来源）
│   │   ├── scene.js           # 地面/渠/剪影/光晕绘制
│   │   ├── effects.js         # 灯火级联、巡船、暮色→深夜过渡
│   │   └── renderer.js        # 渲染器接口（M7 换 Three.js 时替换实现）
│   ├── ui/
│   │   ├── input.js           # 点击/拖拽 → 边状态切换
│   │   ├── tutorial.js        # 三屏规则动效
│   │   ├── notecard.js        # 史实注记卡（DOM 层）
│   │   └── atlas.js           # 漕运图鉴总览（DOM 层）
│   └── levels.js              # 8 关数据（手工设计，逐关验证）
├── tools/
│   ├── verify-levels.mjs      # 逐关跑求解器，断言唯一解
│   └── build.mjs              # 内联打包 → dist/waterweave.html
├── test/                      # node --test 用例
└── dist/waterweave.html       # 最终交付物
```

**为什么这样分**：逻辑层是唯一有"正确性"的部分，必须能用 Node 无浏览器地测；渲染层是主观审美，靠人眼看。把两者锁在接口两侧，任何一边改坏都不会污染另一边。

## 一、公共数据模型（M1 之前先定死，后续所有模块依赖它）

### 1.1 寻址

- 水口（格点）`P(i,j)`，`i ∈ [0..cols]`，`j ∈ [0..rows]`
- 横渠 `H(i,j)`：连接 `P(i,j)–P(i+1,j)`，`i ∈ [0..cols-1]`，`j ∈ [0..rows]`，共 `cols × (rows+1)` 条
- 纵渠 `V(i,j)`：连接 `P(i,j)–P(i,j+1)`，`i ∈ [0..cols]`，`j ∈ [0..rows-1]`，共 `(cols+1) × rows` 条
- 地格 `C(i,j)`，`i ∈ [0..cols-1]`，`j ∈ [0..rows-1]`；其四边为 `H(i,j)`（上）、`H(i,j+1)`（下）、`V(i,j)`（左）、`V(i+1,j)`（右）
- 边 ID 编成单一整数：`H` 占 `[0, cols*(rows+1))`，`V` 从该区间末尾起顺延

### 1.2 状态

```js
// 边状态：0 空白 / 1 开渠 / 2 标记
edgeState: Uint8Array(edgeCount)

// 关卡数据
level = {
  cols, rows,
  numbers: Map<cellId, 0|1|2|3>,
  gates:   Set<pointId>,                 // 闸口水口，回路必须经过
  settlements: [{ pointId, type, name }]  // type: village|dock|granary|bridge|temple
}
```

`numbers` / `gates` / `settlements` 全部用**整数 ID**，不用 `"r,c,dir"` 字符串——渲染热区、校验、求解器都用同一套 ID，避免三处各自解析字符串导致偏移错误。

## 二、里程碑

### M1 — 逻辑层：拓扑 + 模型 + 实时校验器

**交付物**

- `topology.js`：ID ↔ 坐标互转、`cellEdges(cellId)`、`pointEdges(pointId)`、`edgeEndpoints(edgeId)`
- `model.js`：`createLevel()`、`createState()`、`cycleEdge()`、`paintEdge()`、`loadLevel()`
- `validator.js`：`validate(level, state) → { issues: [...] }`，四类检查
  1. **数字**：地格四周开渠数 ≠ 数字 → `issue.digit`（该数字变色，不判负）
  2. **水口分叉**：水口相连渠数 ∉ {0,2} → `issue.degree`（画红点）
  3. **水路成环**：所有渠是否构成**单一闭合回路** → `issue.notSingleLoop`
  4. **闸口**：闸口水口未被回路经过 → `issue.gate`
- `test/` 下 8–10 条用例

**单一回路判定算法**（关键，必须写对）

因每条渠端点度数约束为 0/2：
- 建图：节点为水口，边为开渠的渠
- 若任一节点度数 ∉ {0,2} → 不成立
- 统计"有边的连通分量"个数；**恰好 1 个** 即唯一闭合回路
- 度数全为 2 时，每个分量必为简单圈，故"分量数 = 1"即"回路数 = 1"，无需额外判环
- 用并查集实现，O(E·α)

**验收标准**

```bash
node --test test/
```

- 全绿
- 用例必须覆盖：两环 → fail；断头（含度数 1 的水口）→ fail；单环 → pass；闸口未过 → 报 gate 问题；数字 0 的地格四边有渠 → 报 digit 问题
- `validator` 对任意随机状态不抛异常（对 1000 个随机状态做冒烟测试）

---

### M2 — 求解器 + 逐关唯一解校验工具

**交付物**

- `solver.js`：`solveAll(level, {limit})` → 返回解的数量与前若干条解
- `tools/verify-levels.mjs`：读 `levels.js`，逐关打印 `cols×rows / 解数 / 耗时`，任一关解数 ≠ 1 则退出码 1

**求解器设计**（必须足够快，否则 7×7 关会跑死）

- 三态变量（空白/开渠/标记），**约束传播 + 最受限变量优先回溯**：
  - 地格：`已开渠数 = N` → 其余全标记；`已开渠 + 未定 < N` → 剪枝；`已开渠 + 未定 = N` → 未定全开渠
  - 水口：`已开渠 = 2` → 其余全标记；`已开渠 > 2` → 剪枝；`已开渠 = 1` → 至少再开一条
  - **闭圈剪枝**：若提前形成闭合圈而仍有未定的渠或已开渠 → 剪枝（避免解出多条环）
  - 减法法（数字 3 的格子，四边不可出现两条相邻的"标记"）作为可选加强
- 求解计数上限 `limit = 2`（只需区分 0 / 1 / ≥2）

**验收标准**

- 一个已知的 3×3 单解关卡，求解器返回 1 条解且与手工解一致
- 一个故意多解的关卡，返回 ≥2
- 一个无解关卡，返回 0
- 7×7 关卡求解 ≤ 10 秒（超时视为关卡设计不合格，回炉加数字）

---

### M3 — 教学关可玩 + 三屏规则动效

**交付物**

- `index.html` 调试壳 + `palette.js` + `scene.js`（此阶段只画**可读的几何**，不做最终审美）
- `input.js`：点击一条渠 → `空白 → 开渠 → 标记 → 空白`；按住拖拽可连续涂抹
- 校验器反馈：数字违反时数字变暖红、水口分叉时该水口显示红点；**无任何失败/重开提示**
- `tutorial.js`：三屏自动播放（每屏 3s，可跳过），内容严格按设计稿 4.2 表
- 通关的奖励三段（此阶段用**几何替代**，仅验证时序，不做美术）：灯火级联 1.2s → 巡船 3s → 占位卡片

**验收标准**

- 3×3 教学关（2 个数字：一个 0、一个 2）能解出，且解唯一（跑 M2 工具）
- 三屏动效总时长约 9s，可跳过；首屏无欢迎语、无大段文字
- **人工验收**：找一个未接触过本作的人（或自己去洗把脸当陌生人），20 秒内解出第 0 关
- 全程无分数、无失败判定、无倒计时

### M4 — 8 关关卡数据

**交付物**：`src/logic/levels.js`，按设计稿第五节表格

| 关 | 网格 | 数字数 | 新增 | 对应 | 闸口 |
|---|---|---|---|---|---|
| 0 | 3×3 | 2 | 教学 | —— | 0 |
| 1 | 4×4 | 4 | 无 | 瀍水小渠 | 0 |
| 2 | 5×5 | 6 | 数字 0 | 洛水南岸 | 0 |
| 3 | 5×5 | 7 | 数字 3 | 伊水渡口 | 0 |
| 4 | 6×6 | 8 | 闸口 | 天津桥 | 1 |
| 5 | 6×6 | 9 | 闸口叠加 | 回洛仓 | 2 |
| 6 | 7×7 | 10 | 无 | 含嘉仓 | 0 |
| 7 | 7×7 | 11 | 闸口 + L 形轮廓 | 洛口仓 | 3 |

每关另带：`settlements`（聚落布点，必须落在解出的回路上，否则永远不亮）、`notecard`（史实注记）、`title`。

**验收标准**

- `node tools/verify-levels.mjs` 全部**恰好 1 解**
- 每关的 `settlements` 布点**全部落在最终解回路上**（工具顺带断言）
- 难度曲线满足"新机制只在引入关出现，下一关消化"
- 单人可读性自检：每关手写一遍解题路径，确认无需试错暴力（否则加数字）

### M5 — Canvas 2D 视觉层（完整实现）

**交付物**

- `palette.js`：把设计稿 6.2 表钉成常量，并断言水面 HSL 饱和度 ≤ 30%
- `scene.js`：等距 15° 微倾斜地格、1px `#3A4750` 格线、渠（银蓝，`开渠=生长动画`、`标记=细叉`）、建筑剪影 `#0E161E`
- `effects.js`：
  - 灯火：回路上聚落按**路径顺序**依次亮起，0.15s 柔光绽放，半径 12–20px
  - 巡船：沿回路**匀速**一周（3s），尾迹渐隐银蓝
  - 底色：通关时 `#2A3440 → #16202B` 平滑过渡（ease-out）
- `notecard.js`：史实注记卡（米白 `#EDE6D6` 文字，停留至点击）
- 缓动统一：所有过渡走同一个 `easeOut(t)`，全局禁弹跳

**验收标准**

- 截图比照色板：无越界色值；灯火只出现在聚落（工具断言：光晕绘制调用点的坐标集合 ⊆ 聚落坐标集合）
- 时序：拖动录屏确认 灯火 1.2s / 巡船 3s / 过渡时长
- **人工审美验收**：与《WILDOKU》《指尖生花》并排看，确认"静、克制、不刺眼"，不出现夜景灯光秀感

## 三、依赖顺序与关键路径

```
M1 逻辑层  ──►  M2 求解器  ──►  M4 关卡数据  ──┐
   │                                          ├──► M5 视觉层 ──► M6 图鉴+部署 ──► M7 可选
   └────────►  M3 教学关可玩 + 动效引导  ─────┘
```

- **M1 与 M2 是硬阻塞点**：M2 不通过，后面所有关卡都无法保证唯一解，整个作品的地基就是空的
- M3 可与 M2 并行（M3 先用一个临时关卡，M4 完成后再换真关卡）
- M5 是审美成败所在，也是唯一"主观"的里程碑，必须留足反复打磨余量

## 四、风险与对策（实现期视角）

| 风险 | 触发信号 | 对策 |
|---|---|---|
| 求解器太慢，7×7 跑不出 | M2 单关 > 10s | 加约束传播（3 的减法法）→ 仍慢则减少 7×7 关的数字数或降为 6×6 |
| 关卡唯一解但**不好玩**（靠试错） | 自己手解时频繁猜 | 加数字直到"每步都可推理"；宁可放宽美术，不可放宽可解性 |
| 首关 20 秒达不成 | 陌生人测试超时 | 减到 3×3 单数字（只留那个 2）并强化第二屏动效 |
| 夜景滑向俗艳 | 截图发青发紫、光点满地 | 灯火只在聚落 + 水面饱和度 ≤ 30% 写进断言，不靠自觉 |
| 单文件打包后 ES module 失效 | 双击报 `import` 错误 | `build.mjs` 必须把模块**去 import 化**（顺序拼接 + 作用域隔离），M6 前就要验证 |
| 面试官 90 秒没看懂在干嘛 | 首屏出现文字说明 | 首屏只有网格 + 2 个数字 + 三屏动效；不给任何说明书 |

## 五、Dev 前的三个待定决策（需要你拍板）

1. **打包策略**：是否接受"源码模块 + Node 打包成单文件"？还是要求从一开始就手写单个 `index.html`？
   - 我的建议：源码模块 + 打包。理由：逻辑层要跑 `node --test` 才能验证唯一解，手写单文件会让 M2 无法自动化测试。
2. **音效**：设计稿第八节写"可选：一条环境水声循环"。做还是不做？
   - 我的建议：**做，但只做一条**不超过 8 秒的水声循环（免费素材或 AI 生成），无 UI 音效。理由：治愈向作品音频占体验一半，且成本极低、风险极小。
3. **M7 是否现在就排期**：Three.js 版是加分项但需联网，与"单文件离线即玩"冲突。
   - 我的建议：**先不做**，M6 出链接后视面试时间余量再定。
